# 制作、job和验收

## 视觉继承

1920×1080横屏。默认约736px（38%）固定深灰侧栏，细直分隔线和轻微右投影；右侧镜头聚焦大幅进攻半场或大半场，但模型始终保留完整全场，集中放大具体投篮点；相机适当抬高使地板更饱满，座席、替补席、技术台和地板侧面补足场边环境。中文名主标题、较小淡英文名、透明头像；赛季/范围、场次/日期均在左栏。头像与赛季区之间留出独立间距。

计数零起。红命中、白未中；Made为圈，Missed为叉。当前起点与轨迹同步高亮，旧标记降亮，线条短时淡出，结尾汇总渐亮。固定数量刻度的五区堆积柱，不用固定满宽百分比条；左右底角合并。数字只显示命中/出手和命中率。乔丹采用公牛红白；其他球员若没有新配色要求仍可继承本风格。

不恢复已取消的撕纸、纸芯、毛边、23、最后一投照片/原声段、底部文案、统一刻度文字、区域未中数字。署名仅使用用户指定文字；当前用户的乔丹模板署名为created by 篮坛巨编，右上方避免篮架遮挡。用户的新要求优先。

球场必须依据球员/球队/年份查参考，logo、配色、禁区和文字要匹配。模板公牛场地是参考重建，不能说100%实拍复刻；其他球队不可仅改名字后保留Bulls标志。始终使用完整场地和两套朝内篮架，以近景构图自然呈现半场或大半场；保留原始贴图的英尺比例，不横向拉伸、不裁切贴图、不在中线做地板断面，后方支架、玻璃板、篮圈、网都需有几何，当前无计时器。按相机远近绘制设施，后方视角不把贴图无故镜像。

最新运镜取消360°绕场，模仿科比参考的稳定近景：方位从-6°极慢单向移动到2°，相机距离推进2%，不回摆。投影中心只以中间姿态校准一次，整段固定；不能再逐帧跟随投篮云包络移动中心。左栏与署名固定，球场、圈叉、轨迹始终共享相机和同一固定投影中心。

最新按赛季数量选择时序、宽侧栏见 [整季齐发模式](season-batch.md)。轨迹单季默认20秒，分区总结默认追加6秒。

## job和执行

模板所有文件已改为相对路径。先复制到新项目，输出放用户任务的outputs；中间文件放work。不要直接在安装目录里渲染或改用户模板。

```sh
python scripts/create_project.py <work/新项目>
python scripts/configure_video.py <work/新项目>
python scripts/apply_half_court.py <work/新项目>
python scripts/apply_scene_framing.py <work/新项目>
python scripts/apply_stable_camera.py <work/新项目>
python scripts/validate_data.py <work/新项目/shots.csv> --job <work/新项目/job.json>
python scripts/render_video.py <work/新项目> --output <work/检查图> --mode check
python scripts/render_video.py <work/新项目> --output <outputs/项目名> --mode video
```

新球员由agent准备job.json，传入create_project的--job/--shots/--court/--portrait/--logo。job字段以assets/jordan-template/job.json为准：

- player_id/name_zh/name_en、season_label/phase_label、team_label/credit必须更新。
- expected_attempts/expected_made/expected_games来自已核对的选定范围，不能延用2419/1124/103。
- 图片路径由create_project复制。portrait_crop按新头像实际边界调整。court_texture_box=[纵向baseline像素0,纵向baseline像素1,横向sideline像素0,横向sideline像素1]；在这张参考图中分别对应94ft×50ft的场内边界。四边范围要依新球场图片实际标线校准。
- bar_scale取覆盖最大分区最终出手数的整洁数值，五区共用且整段固定；不能按每区自己的最终数量分别归一化。
- source_duration/source_fps与delivery_duration/delivery_fps为源与交付时间基准。优先使用一致的60fps，不能用光流补弧线，以免圈叉错位。
- 逐球模式使用20秒单季默认或用户指定时长，同帧可启动相邻多次出手，每条都要绘制并经历完整弧线的可见帧。不要使用旧N/29或N/38公式擅自延长，不抽样漏球。源与交付帧率保持一致优先，避免转码丢掉轨迹。

运行时选环境内Python，依赖numpy、Pillow、pyarrow、imageio-ffmpeg。FFMPEG_BINARY可显式指定。SHOT_VIDEO_WORKERS默认4，可根据设备调低。不复用原电脑的绝对路径、全局字体或旧聊天的文件。

## 验收重点

1. 数据范围、总计与独立统计一致；缺场/缺点和可疑重复保留报告，不用随机点补齐。
2. 第一编码帧零出手；10季及以内按出手顺序有线、有圈叉并同步累积；超过10季按季齐发。相机每次变化后重新投影所有标记。逐条数值同点之外，隔离检查命中、未中、近筐、边角与远投起点的屏幕效果；多线叠加时当前起点应能辨认。
3. 首、中、后所有前缀满足命中+未中=总出手，五区和=总出手；全零无柱，长度按累计数量增长。不要写只验证同一个实现的空测试。
4. 首、中、尾实际截图。确认近景稳定、全段只约8°移动，不能又绕场360°，完整双端设施存在，允许远端因近景构图自然出画；无静态页脚遮罩、无旧的地板视口裁切。原工程曾在y1028截断，因此不能仅删除底部文字就当去黑边。
5. 完整解码最终编码文件，核对时长、分辨率、帧数；查看实际成片而非只看逻辑渲染。停止无必要的循环美化。

只检查小改动相关的风险。模板可用--preview-seconds 1做短编码冒烟检查；完整预览和正式渲染以当前目标为准。

半场是镜头取景，不是模型裁切。COURT_LIT和FLOOR_CORNERS必须始终保持完整全场；不要在中线终止地板或产生悬浮切面。x_legacy/y_legacy单位与篮心原点不变，中线外真实远投也保留。只做极轻单向位移，不做360°环绕或左右回摆。

新版半场构图使用相机高度130ft、投影焦距2800、画面中心(1328,550)，这些是旧版大场景基础参数；最终须应用稳定镜头配置（8°/2%）；它们是1920×1080及736px侧栏下的已验证初值。对于新素材仍检查121个采样时刻的出手点/弧线完整投影边界，不能靠放大截掉边角投篮。看台以克制灰色呈现，环境保持低于轨迹亮度；此为场边示意建模，不能声称真实复刻了球馆座椅排布。

篮筐后方的基线区域保持干净，不添加座椅图标或近场排椅；侧边座席和技术台保留。远处暗看台可作为环境背景。

最新近景再把相机与注视点的距离乘0.88，保持稳定的微幅单向移动与缓慢推进；旧包络偏移逻辑由稳定镜头覆盖：投影中心在中间姿态校准后锁定，仅以极轻微相机运动维持边角可见，不让画面随点云来回漂移。所有场景几何、圈叉和轨迹必须共用同一投影，不可只移动背景。

## 分区总结页

轨迹结束后追加约6秒：原左栏保持内容、尺寸和位置；深灰背景从左栏边缘向右铺开，只有右侧3D球场切换成同背景的俯视半场。总结区域单独展示左右底角、左右侧翼、弧顶三分、三个中距离、禁区短两分和篮下。比例用每个区域自身命中/出手计算，十区合计须等于全片总计，合并后须与原左栏五区完全一致。左/右以球员面向篮筐的身体方向为准。当前俯视图篮筐在下方，因此球员左侧位于图面右侧（world x>0），球员右侧位于图面左侧（world x<0）。分类函数、标签位置、命中/出手和联盟基准必须同步对应，不能按屏幕左右命名。

六边形大小表示出手密度；颜色表示球员同区域命中率相对当赛季联盟的百分点差。先用全联盟parquet，按相同season、season_type_id和区域几何规则计算命中总和/出手总和；底部只用“低于均值—五档色块—高于均值”与频次大小图例，不显示pp、阈值或长说明。标签优先清晰，避免被球场线条、密度格或队标遮住。独立保留左底角和右底角是用户明确要求；不得用左栏合并规则覆盖总结图。

```sh
python scripts/append_zone_summary.py <project> --video <轨迹MP4> --league-shots <全联盟赛季parquet> [更多赛季parquet...] --output <最终MP4>
```

脚本从已有MP4最后一帧保留左栏；拼接后完整解码。检查展开中间帧与最后一页，确认左栏始终可见、各区域数字可读，左右底角加总等于左栏底角统计。中间素材保存在项目summary-work目录。

展开必须能看出左栏右边缘向右移动（默认1.5秒），移动投影仅在转场中存在。原栏边缘竖线须清除，展开背景取样原左栏底色，最终画面无竖缝；左侧内容和位置全程保留。

右侧总结页标题固定为“区域投篮”；标题下不放赛季、赛事类型和左右方向说明，原左栏赛季信息保留。


## 审定样式与执行

最新样式以SKILL.md“最新审定排版与安全区”和assets/approved-preview.png（静态图）为准。保留两行赛季信息、四列总计、正常宽度英文名、宽松柱状图、不显示右侧标题/右上Logo。1080顶部96/底部144，横向内容重排并右移69，不能再使用全图等比缩小补边。

render_video.py在已有configure/半场/场边/稳定相机及CBA适配之后，自动调用apply_approved_layout.py，复用approved_sidebar.py绘制每一帧同款侧栏，只给3D投影做固定安全区校准。同一相机投影同时驱动轨迹和圈叉，禁止每帧追随投篮云。

完整job补充height_cm/weight_kg/birth_date/age_as_of/league_season_number，scope_label、record_label、date_label可显式给定真实口径；没有资料时模板只显示—，agent应在正式交付前核实补全。球龄按真实参加联盟赛季计，非机械年份差。

append_zone_summary.py/append_cba_summary.py调用render_static_summary.py使用同款十区图，左栏按源片冻结；新成片已留白，不再调用safe_area.py给整段二次缩小。旧源片须从项目重新生成，不能混用旧侧栏与新总结。只交轨迹时render_video.py输出也已包含安全区。每帧的source尺寸/FPS不变。
